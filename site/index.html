How it works

Draw the map once. It watches every edit after that.

01

Declare the systems

fault init drafts faultline.yml from your folders and imports. Rename the boxes and write the lines that matter.

systems:
  - { id: web, paths: [src/web/**] }
  - { id: api, paths: [src/api/**] }
  - { id: db,  paths: [src/db/**] }
rules:
  - deny: web -> db
    reason: the UI goes through the API
02

Watch it live

fault map redraws as you or an agent edit. New dependencies turn green, crossed lines turn red, each with the import behind it.

03

Stop the crossing

Agents check the map before they write, and hear about a crossed line the moment it happens. fault check holds it in CI.

✗ Crosses a fault line:
  Web UI → Database
  src/web/page.tsx imports query
  from client.ts.
  Allowed route: web → api → db
Any agent, any model

One file every agent and every teammate respects.

fault setup wires in the MCP server, hooks, AGENTS.md and a pre-commit check for the agents your repo uses. The same faultline.yml gates pull requests in CI.

# .github/workflows/faultline.yml
on: pull_request
jobs:
  faultline:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: anzal1/faultline@v0
# Every PR gets one comment: what changed in
# the architecture, and the imports behind it.
# The check fails when a line is crossed.
Stays true

A map that keeps itself honest.

A map nobody updates starts lying. So where code lives updates itself, and what may depend on what stays a human decision.

  • New folders are placed in the system their imports go to.
  • Rules are suggested from your history: if A has never imported B in 200 commits, keep it that way?
  • Only a person can loosen a rule. The agent hook refuses it, and CI fails until someone approves.
$ fault sync

Footprint

See what your code costs to load.

Pick an entry point and the map lights up everything it loads at startup: how much of each system, which packages, the shortest import chain behind any file, and the one import that would drop the most if you cut it.

On Astro's production entry it found zod imported at startup to read a couple of constants.

Install

Two minutes, one repo.

Node 20 or newer. Nothing leaves your machine.

$ npm install -g @anzalabidi/faultline
$ fault init      # propose systems, write faultline.yml
$ fault map       # open the live map
$ fault setup     # connect your agents
$ fault check     # the CI gate
